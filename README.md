# Сервис инвентаризации офисных помещений

Учебный проект по дисциплине "Технологии разработки приложений на базе фреймворков".

## Назначение

Сервис помогает проводить инвентаризацию в офисе: вести учет предметов по помещениям и проверять, все ли на месте. Проверяющий обходит помещение и записывает, сколько предметов нашел и в каком они состоянии. Сервис сравнивает это с учетом и показывает результат: недостачу, излишки и предметы, которые пора заменить.

## Целевая аудитория

- сотрудники хозяйственного отдела, которые отвечают за имущество офиса;
- бухгалтерия, которой нужны итоги инвентаризации;
- ответственные за помещения.

## Предметная область

В офисе есть помещения: кабинеты, переговорные, серверная. В каждом помещении находятся предметы: мебель и техника. У предмета есть инвентарный номер, количество по учету, цена, дата покупки и срок службы. Время от времени в помещении проводят проверку: сравнивают фактическое количество предметов с учетом и смотрят их состояние. По каждому предмету записывается результат.

Правила:

- если предметов меньше, чем по учету, это недостача, ее сумма считается по цене предмета;
- если предметов больше, чем по учету, это излишек;
- если предмет неисправен или старше срока службы, его нужно заменить.

## Основные сущности

- Помещение: название, этаж, ответственный.
- Предмет: инвентарный номер, название, помещение, количество по учету, цена, дата покупки, срок службы.
- Проверка: помещение, дата, проверяющий.
- Результат: проверка, предмет, фактическое количество, состояние, итог (в наличии, недостача, излишек, требуется замена).

## Основные функции

Сейчас программа умеет:

- показывать помещения с количеством и стоимостью предметов;
- показывать предметы помещения и искать предмет по названию или инвентарному номеру;
- добавлять предмет, переносить его в другое помещение и списывать;
- проводить проверку помещения: по каждому предмету считать разницу с учетом, сумму недостачи, возраст и нужна ли замена;
- показывать результаты всех проверок с итогами;
- считать статистику: количество и стоимость имущества, сколько помещений проверено, общая сумма недостачи.

Планируется:

- добавление и изменение помещений;
- пользователи и роли;
- отчеты по проверкам за период.

## Структура проекта

- main.py - меню программы и вывод на экран;
- rooms.py - поиск и сортировка помещений;
- items.py - предметы: поиск, сортировка, добавление, перемещение, списание;
- checks.py - проверки, результаты, итоги и статистика;
- calc.py - расчеты из первой версии: разница, сумма недостачи, возраст, замена, итог;
- storage.py - загрузка и сохранение данных в JSON;
- utils.py - ввод данных с проверкой ошибок;
- data/ - файлы с данными;
- tests/ - тесты pytest.

## Формат данных

Данные хранятся в папке data в четырех JSON-файлах. Программа загружает их при запуске и сохраняет после каждого изменения.

rooms.json - помещения:

```json
{
    "id": 1,
    "name": "Кабинет 204",
    "floor": 2,
    "responsible": "Иванова А. С."
}
```

items.json - предметы, room_id - номер помещения из rooms.json:

```json
{
    "id": 1,
    "number": "1001",
    "name": "Кресло офисное",
    "room_id": 1,
    "quantity": 12,
    "price": 4500.5,
    "purchase_date": "2022-03-15",
    "service_life": 7
}
```

checks.json - проверки:

```json
{
    "id": 1,
    "room_id": 2,
    "date": "2026-10-05",
    "inspector": "Петров Д. И."
}
```

results.json - результаты, check_id - номер проверки из checks.json:

```json
{
    "id": 3,
    "check_id": 1,
    "number": "1007",
    "name": "Стул",
    "expected": 10,
    "actual": 9,
    "is_working": true,
    "needs_replacement": false,
    "status": "недостача",
    "shortage_cost": 2300.0
}
```

Даты хранятся в формате ГГГГ-ММ-ДД.

## План развития

На следующих этапах планируется:

- классы для помещения, предмета, проверки и результата;
- веб-приложение на Django: страницы помещений, предметов и проверок;
- подключение базы данных;
- регистрация пользователей и роли;
- REST API для предметов и проверок;
- контейнеризация (Docker);
- настройка CI/CD.
