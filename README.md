# Сервис инвентаризации офисных помещений

Учебный проект по дисциплине "Технологии разработки приложений на базе фреймворков".

## Назначение

Сервис помогает проводить инвентаризацию в офисе: вести учет предметов по помещениям и проверять, все ли на месте. Проверяющий обходит помещение и записывает, сколько предметов нашел и в каком они состоянии. Сервис сравнивает это с учетом и показывает результат: недостачу, излишки и предметы, которые пора заменить.

Программа умеет:

- показывать помещения с количеством и стоимостью предметов;
- показывать предметы помещения и искать предмет по названию или инвентарному номеру;
- добавлять предмет, переносить его в другое помещение и списывать;
- проводить проверку помещения и считать результат по каждому предмету;
- показывать результаты всех проверок с итогами;
- считать статистику по имуществу и проверкам;
- хранить данные между запусками.

## Целевая аудитория

- сотрудники хозяйственного отдела, которые отвечают за имущество офиса;
- бухгалтерия, которой нужны итоги инвентаризации;
- ответственные за помещения.

## Предметная область

В офисе есть помещения: кабинеты, переговорные, серверная. В каждом помещении находятся предметы: мебель и техника. Время от времени в помещении проводят проверку: сравнивают фактическое количество предметов с учетом и смотрят их состояние. По каждому предмету записывается результат.

Правила:

- если предметов меньше, чем по учету, это недостача, ее сумма считается по цене предмета;
- если предметов больше, чем по учету, это излишек;
- если предмет неисправен или старше срока службы, его нужно заменить;
- списанный предмет не удаляется из учета, а помечается списанным и в проверках больше не участвует.

## Основные классы

### Room - помещение

Атрибуты:

- `id` - номер помещения;
- `name` - название;
- `floor` - этаж;
- `responsible` - ответственный.

Методы:

- `__str__()` - строка для вывода помещения;
- `from_data()` - создает помещение из данных JSON;
- `to_data()` - превращает помещение в данные для JSON.

### Item - предмет

Атрибуты:

- `id` - номер записи;
- `number` - инвентарный номер;
- `name` - название;
- `room` - объект `Room`, в котором стоит предмет;
- `quantity` - количество по учету;
- `price` - цена за штуку;
- `purchase_date` - дата покупки;
- `service_life` - срок службы в годах;
- `is_written_off` - признак списания.

Методы:

- `total_cost` - стоимость всех штук (свойство);
- `get_age_years()` - возраст предмета на дату;
- `needs_replacement()` - нужна ли замена: предмет сломан или старше срока службы;
- `move_to()` - перенос в другое помещение;
- `write_off()` - списание;
- `is_valid_quantity()` - проверка количества (статический метод);
- `__str__()`, `from_data()`, `to_data()`.

### Check - проверка

Атрибуты:

- `id` - номер проверки;
- `room` - объект `Room`, который проверяли;
- `date` - дата проверки;
- `inspector` - проверяющий.

Методы: `__str__()`, `from_data()`, `to_data()`.

### Result - результат

Атрибуты:

- `id` - номер результата;
- `check` - объект `Check`;
- `item` - объект `Item`;
- `expected` - количество по учету на момент проверки;
- `actual` - фактическое количество;
- `is_working` - исправен ли предмет.

Свойства:

- `difference` - сколько штук не хватает: плюс - недостача, минус - излишек;
- `shortage_cost` - сумма недостачи;
- `needs_replacement` - нужно ли заменить предмет;
- `status` - итог: в наличии, недостача, излишек или требуется замена.

Методы: `__str__()`, `from_data()`, `to_data()`.

## Взаимодействие объектов

Объекты хранят ссылки друг на друга, а не номера:

```text
Result
 ├── check → Check
 │            └── room → Room
 └── item  → Item
              └── room → Room
```

Поэтому данные связанных объектов доступны напрямую: `item.room.name`, `result.item.price`, `result.check.room.name`.

Результат сам считает свой итог: количество и цену он берет у своего предмета, а дату проверки - у своей проверки.

## Основные операции

Функции работают со списками объектов и лежат рядом с классами:

- помещения: поиск по номеру, сортировка;
- предметы: предметы помещения, поиск, сортировка, добавление, перемещение, списание, подсчет количества и стоимости;
- проверки: создание проверки, поиск по номеру;
- результаты: добавление результата, результаты одной проверки, итоги, статистика.

## Хранение данных

Данные хранятся в JSON-файлах:

- `data/rooms.json`;
- `data/items.json`;
- `data/checks.json`;
- `data/results.json`.

При загрузке данные из JSON превращаются в объекты `Room`, `Item`, `Check` и `Result`, а связи между ними восстанавливаются. При сохранении объекты превращаются обратно в данные JSON, и вместо связанных объектов записываются их номера: `room_id`, `check_id`, `item_id`.

Пример предмета в `items.json`:

```json
{
    "id": 1,
    "number": "1001",
    "name": "Кресло офисное",
    "room_id": 1,
    "quantity": 12,
    "price": 4500.5,
    "purchase_date": "2022-03-15",
    "service_life": 7,
    "is_written_off": false
}
```

Назначение модулей:

- `main.py` - меню программы и вывод на экран;
- `models/rooms.py` - класс `Room` и функции для списка помещений;
- `models/items.py` - класс `Item` и функции для списка предметов;
- `models/checks.py` - класс `Check` и функции для списка проверок;
- `models/results.py` - класс `Result`, итоги и статистика;
- `models/common.py` - общая функция для выдачи следующего номера;
- `storage.py` - загрузка и сохранение: JSON в объекты и обратно;
- `utils.py` - ввод данных с проверкой ошибок.
