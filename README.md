# Сервис планирования использования помещений

Учебный проект по дисциплине "Технологии разработки приложений на базе фреймворков".

## Назначение

Сервис помогает планировать мероприятия в помещениях: аудиториях, переговорных, конференц-залах. Организатор подает заявку, а сервис проверяет, подходит ли помещение: хватит ли мест, есть ли нужное оборудование, работает ли помещение в это время и не занято ли оно другим мероприятием.

## Целевая аудитория

- администраторы, которые ведут расписание помещений;
- организаторы мероприятий (преподаватели, сотрудники, руководители студенческих клубов);
- участники мероприятий.

## Предметная область

В организации есть помещения. У каждого помещения есть вместимость, оборудование и часы работы. В помещениях проводятся мероприятия: занятия, встречи, собрания, конференции. Каждое мероприятие занимает помещение на определенную дату и время.

Правила:

- в одно время в помещении может быть только одно мероприятие;
- участников не может быть больше, чем мест;
- мероприятие должно проходить в часы работы помещения;
- если мероприятию нужен проектор, он должен быть в помещении.

## Основные сущности

- Помещение: название, тип, вместимость, оборудование, часы работы.
- Мероприятие: название, организатор, количество участников, нужное оборудование.
- Пользователь: имя, контакты, роль (администратор, организатор, участник).
- Расписание: мероприятие, помещение, дата, время начала и конца, статус заявки.

## Основные функции

Сейчас программа умеет:

- показывать помещения (по вместимости) и искать их по названию;
- подбирать свободные помещения под мероприятие по дате, времени, количеству участников и проектору;
- бронировать помещение с проверкой заявки: часы работы, пересечения с другими мероприятиями, вместимость, проектор;
- отменять бронирования;
- показывать расписание помещения на день и все бронирования;
- добавлять помещения;
- считать статистику: количество бронирований, занятые часы, самое загруженное помещение.

Планируется:

- перенос бронирований;
- подтверждение заявок администратором;
- пользователи и роли.

## Структура проекта

- main.py - меню программы и вывод на экран;
- rooms.py - помещения: поиск, подбор, сортировка, добавление;
- bookings.py - бронирования: проверка заявки, создание, отмена, расписание, статистика;
- checks.py - проверки заявки из первой версии проекта;
- storage.py - загрузка и сохранение данных в JSON;
- utils.py - ввод данных с проверкой ошибок;
- data/ - файлы с данными;
- tests/ - тесты pytest.

## Формат данных

Данные хранятся в папке data в двух JSON-файлах. Программа загружает их при запуске и сохраняет после каждого изменения.

rooms.json - список помещений:

```json
{
    "id": 1,
    "name": "Конференц-зал Сириус",
    "capacity": 40,
    "has_projector": true,
    "opens": "08:30",
    "closes": "21:00"
}
```

bookings.json - список бронирований, room_id - номер помещения из rooms.json:

```json
{
    "id": 1,
    "room_id": 1,
    "title": "Защита курсовых проектов",
    "date": "2026-10-15",
    "start": "10:00",
    "end": "12:30",
    "participants": 30,
    "needs_projector": true
}
```

Дата хранится в формате ГГГГ-ММ-ДД, время - ЧЧ:ММ.

## План развития

На следующих этапах планируется:

- классы для помещения, мероприятия, пользователя и бронирования;
- веб-приложение на Django: страницы помещений, расписания и заявок;
- подключение базы данных;
- регистрация пользователей и роли;
- REST API для расписания и бронирований;
- контейнеризация (Docker);
- настройка CI/CD.
